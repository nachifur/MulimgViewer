# 并行视频性能退化修复与复测

本轮消除了原图拼接流水线的重复限流，补齐自动分辨率下的预览复用，减少重复文件操作和文字绘制开销。实际并行播放明显快于修改前；尚未实现按线程预算线性扩展，尤其 Maximum 的收益仍有瓶颈，不能把预算比例当成 FPS 比例。

## 测试条件

- Windows，本机 22 个逻辑 CPU、约 31.4 GiB RAM；各模式使用同一份可用内存参考值。
- 输入：`D:\ncfey\Desktop\test_img\test_video`，24 个视频，12 路 1080×1080、12 路 1280×720。
- 读取 `src/mulimgviewer/configs/userdef_config.json` 的 output 配置，保留 4×6 布局、每路 1×2 帧、0.15 缩放、标题、放大镜及其他显示参数。最终并行画面为 2204×766。
- 吞吐测试临时关闭 `parallel_to_sequential` 和 `parallel_sequential`，人工 interval 临时设为 0.001 秒。用户配置文件没有改写。
- cache_frames=2、cache_multiplier=1；完整外层窗口为 5 页。普通播放仅使用默认原图插件。
- 每次运行独立进程及新磁盘缓存，预热 6 次切换，再测 30 秒。计数点为 wx 的实际 display_bitmap 完成；FPS 指整张拼接页的切换速率，不是源视频编码帧率，也不是显示器刷新率。
- CPU 为软件及其解码子进程占整机逻辑 CPU 的平均比例。RSS 含子进程，不能与缓存字节数混为一谈。

## 定位与修改

1. **重复限流导致串行。** PipelineWorkers 已按总预算和内存允许多个拼接页借用闲置拆帧名额，但算法阶段再次按 stitch 的保留名额限流。保留名额为 1 时，所有借用的拼接页仍排队。普通原图页只有一个子计算任务，现在沿用上层已核算的并发预算；自定义算法的多任务限额保持独立保护。
2. **自动分辨率预览没有命中。** 原先仅为正数分辨率构建预览，且没有计入显示缩放。现在使用与实际布局一致的来源分辨率归一化，支持混合尺寸和串行边界；拆帧时从已有像素生成准确的显示预览，后续拼接复用。裁剪和自定义算法保留各自的原始输入路径。
3. **首次拼接内存估算忽略缩放。** 现在按显示缩放、网格、间距和标题估算画布，避免把小预览按全分辨率巨幅画面预留内存。完整原始帧的工作内存仍单独核算。
4. **重复文件操作。** 原图恒等路径不再重复打开同一输入头部；内部 JPEG/PNG 读取使用文件流，减少 Pillow 在 Windows 上的重复路径解析。
5. **标题与像素复制。** 增加有界文字测量和单色字形缓存（字形最高 8 MiB、最多 1024 条），移除每个标题用于测量的千行空画布；透明度改用 Pillow 原生操作。测试逐像素验证输出与输入不被修改。
6. **额外预算缺少可用缓存和搜索范围。** 像素加速缓存按模式内存预算的 8% 增长，最高 1 GiB；降档立即收缩。并发探测不再因一个较慢的相邻候选就停止探索更低并发。

原始帧、算法结果及各层拼接图仍保存在磁盘；双层窗口、版本隔离、引用保护和窗口外清理保留。不会按“视频数×4K×全部帧”无界常驻内存。

## interval 与原配置验证

`diagnostic_unpaced_max` 仅在测试进程停用自动间隔预测，立即消费就绪页，约为 2.64 FPS；其 P95 切换间隔约 818 ms。该实验没有带来明显高于正常预测的吞吐，因此本轮没有修改正式播放的 interval 算法，也没有通过固定延迟掩盖供给不足。

`verified_config_serial` 保留原配置的 parallel_to_sequential=true，人工间隔仍仅为吞吐测试临时降至 0.001；实测约 0.93 页/秒，连续通过多个视频的串行边界。这个布局每页消费约 48 个原始帧，不能与每路两帧的真正并行模式混称。

用户原配置的人工 interval=1.0 秒会限制切换速度。复现上表需在 GUI 中设为 0.001，并关闭两个串行转换选项；其余布局和缓存保持原配置。程序继续尊重人工间隔下限。

## 线性收益的实际边界

Maximum 两次结果均高于本轮 Performance，但线程预算从 16 增至 22（+37.5%），平均 FPS 仅约增加 11%；线性目标尚未达成。

总预算是可用上限。实际吞吐同时受原始帧依赖、可生产页数、Python/字体处理的串行部分、JPEG/PNG 编解码和文件操作制约。当前半径 2、倍率 1，仅有两页前向余量；增加内存不会自动扩大用户指定的外层窗口。计时中的逻辑 I/O 数量也不能直接证明物理硬盘已经饱和。

进一步接近线性需要对剩余串行工作做隔离实测，评估进程化渲染/编码或更深的受限预取；本轮没有引入这些尚未验证的架构变更。
