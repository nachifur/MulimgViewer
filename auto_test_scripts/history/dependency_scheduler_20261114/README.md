# 调度器改造验证记录

本轮实现：依赖回调推进四阶段任务；统一算法计算执行池；就绪的最终合成可借用空闲额度；下游资源让路；后台合并清理；解释器退出时排空元数据步骤。

## 实际视频测试

输入为 manifest.json 中的 24 个视频，配置来自本目录 config.json。Maximum；主布局 1,6；单图布局 1,1；unit 3,1；缩放 0.1,0.1；算法画布 2,1；show_all_func=true、show_unit=false；cache_frames=4、cache_multiplier=2；人工 interval 下限 0.001 秒。基准工具会调整输入与间隔，并非直接使用原配置中的 1 秒人工下限。实际显示按画布容量选取算法。输出大小 758×224。

| 指标 | 修改前（30 秒） | 中间版（30 秒） | 最终版（60 秒） |
|---|---:|---:|---:|
| 实际显示 FPS | 0.500 | 0.700 | 0.883 |
| 最终缓存供给 FPS | 0.500 | 0.667 | 0.866 |
| 整机平均 CPU | 24.30% | 29.27% | 29.84% |
| 帧间隔 P95 | 6.933 秒 | 1.907 秒 | 2.135 秒 |
| 首屏耗时 | 4.078 秒 | 6.328 秒 | 6.296 秒 |
| 进程内存峰值 | 1783 MiB | 1836 MiB | 2068 MiB |

前两次为相同测量时长的对比；最终版用更长测试确认持续供给，并增加了就绪 Compose 借用额度的修复。测量时长及执行时间不同，最终版相对前测的约 77% 显示 FPS 增幅仅作为观测，不视为重复统计或严格控制实验结论。每次只有一次样本，后台其他应用、文件系统缓存及系统可用内存会影响结果。

最终版帧序连续、无播放状态错误、无超时，基准进程退出码为 0，正常完成后台收尾。供给 FPS 与显示 FPS 接近，不只是消耗启动缓存。CPU 尚未饱和，且首屏变慢、峰值内存有所增加，不能据此承诺任意算法线性加速或 Maximum 总能优于 Performance。未通过人为提高 interval 制造提速。

中间版及旧 after-final 诊断运行在退出时曾挂起；其结果保留用于定位，不代表当前版本关闭行为。最终有效结果是 release/result.json 和 release.log。
